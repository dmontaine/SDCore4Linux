# regress-map.txt - which sandbox suites a changed file selects.  Read by gplbld/regress-changed.py (regress.sh --changed).
#
# WHY IT EXISTS.  The owner asked for TARGETED regressions on 14 Oct 2026 and again on 15 Oct ("i have previously asked that
# regressions be more targeted"); the 14 Oct answer was speed (--jobs 8) and the full set kept being run for every change.
# This file is the targeting: a change runs the suites of the area it touches, not the 93 of the whole set.
#
# SYNTAX.  One rule to a line; '#' starts a comment; blank lines are ignored.
#   @name = suite suite @other          a group of suites (a group may use groups defined above it)
#   pattern : suite suite @group        a rule: a changed file whose path matches PATTERN selects these suites
#   pattern : none                      a rule: the file needs no sandbox suite (the free checks, which --changed always
#                                       adds, are the check)
# A PATTERN is an fnmatch pattern ('*' matches '/' too) on the path under sdb_ai/sd64, or - when it begins with '/' - on the
# path under the repository root (/CLAUDE.md, /installsdcore.sh).  THE FIRST RULE THAT MATCHES A FILE IS THE ONLY ONE USED, so
# the specific rules come before the coarse ones at the end.  The suite word @self, on a rule for gplbld/sandbox-*.py, is the
# suite that file is.  A changed file that NO rule matches stops the run (exit 2): add a rule, do not guess.
#
# MAINTENANCE.  A new suite goes into regress.sh's ALL_SUITES AND into at least one rule below (test-regress-changed-units.py
# fails on a suite no rule names, and on a rule that names a suite regress.sh does not have).  The coarse rules at the end are
# deliberately broad (@core); when a change keeps landing in one of them, add a specific rule above it.
